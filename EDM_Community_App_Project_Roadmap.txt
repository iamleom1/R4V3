EDM / Rave Community App (Dating-Style) - Production Roadmap (M1-M6)

Assumption:
Mobile-first dating/community app for the EDM/rave scene, built with React Native (Expo) + Supabase.

M1. Foundation (1-2 weeks)
- Product requirements v1 (features, roles, safety rules, success metrics)
- Technical architecture decisions
- Repo setup (Expo, TypeScript, linting, formatting, CI)
- Env management (dev/staging/prod)
- Supabase project setup
- Database migrations + baseline RLS strategy
- Design system foundation (colors, type, spacing, components)

Deliverable:
Runnable app shell + backend skeleton with clean project structure.

M2. Identity + Profiles (2-3 weeks)
- Auth (email, optional phone later)
- Onboarding flow (age gate 18+, consent, community guidelines)
- Profile creation/editing
- Photo upload/storage
- Music preferences + vibe tags
- Safety/privacy controls (visibility basics)

Deliverable:
Users can sign up and create real profiles.

M3. Events + RSVP (2-4 weeks)
- Event ingestion layer (Ticketmaster/SeatGeek normalization)
- events, event_sources, event_rsvps tables
- Event discovery screen (search/filter by city/date/genre)
- RSVP states (Going, Interested)
- Event detail screen

Deliverable:
Event-centered social graph exists.

M4. Matching Engine (3-4 weeks)
- Community mode (default)
- Dating mode (explicit opt-in)
- Swipe/feed candidate generation (event overlap + preferences + safety filters)
- swipes, matches logic
- Mutual match creation + dedupe constraints
- Match list UI

Deliverable:
Users can match around shared events/interests.

M5. Chat + Safety Ops (3-4 weeks)
- Realtime 1:1 chat after match (messages)
- Read receipts / typing indicators (optional first pass)
- Block/report flows
- Moderation queue data model + admin-facing internal tools (basic)
- Rate limits / anti-abuse controls / bot friction
- Push notifications (new match/message)

Deliverable:
Full core loop with safety enforcement.

M6. Quality, Growth, Launch Readiness (3-6 weeks)
- Analytics instrumentation (activation, retention, match/chat funnel)
- Error/crash monitoring (Sentry)
- Performance pass (image loading, query optimization, caching)
- QA matrix (iOS/Android devices, edge cases)
- Beta release (TestFlight / Play Internal Testing)
- Monetization foundation (RevenueCat, feature flags; can launch disabled)
- Legal docs integration (Privacy, Terms, Guidelines)

Deliverable:
Production-ready beta with observability and launch checklist.

Cross-Cutting Priorities (Dating-App Specific)
- Trust & safety from day one (not post-launch)
- RLS and privacy boundaries enforced at DB level
- Moderation tooling early enough to operate the app
- Clear consent UX for dating mode vs community mode
- Anti-spam/bot protections before open beta

Suggested Build Order
1. Finalize schema + RLS design
2. Bootstrap app + navigation + auth
3. Build onboarding/profile flows
4. Add events + RSVP
5. Add matching + chat
6. Add safety/moderation + QA hardening
